## 简介

客户服务模块是基于企业运营平台（OpsHub）开发的一套完整的客户服务管理系统。该模块现已实现电商客服系统的完整功能，包括在线咨询服务、会话管理、消息传递和实时通信等核心功能。

**更新** 模块已从传统的工单管理扩展为包含电商客服系统和客户服务工作台的完整服务体系，支持多种咨询类型、实时聊天、会话状态管理以及执行员产品线授权的精准通知系统。新增的客户服务工作台提供了一体化的咨询处理界面，执行员产品线授权管理确保了通知的精确匹配，全局通知组件提供了便捷的新咨询提醒功能。

**新增** 最重要的更新是引入了BPM任务分配监听器功能，实现了事件驱动的任务同步机制，彻底替代了原有的手动同步方式，消除了时序竞争问题。这一机制通过监听Flowable引擎的TASK_ASSIGNED事件，在BPM任务分配完成后立即同步更新工单处理人信息，确保数据一致性。

**新增** WebSocket通知系统已从传统的广播机制重构为基于执行员产品线授权的精准匹配通知系统，显著提升了通知的相关性和效率。系统现在支持角色×产品线的交集匹配，确保执行员只接收与其职责相关的咨询通知。

**新增** 新增了DealerSelectDialog组件，为用户提供直观的经销商选择界面，支持单选和自动选择功能。该组件在创建会话时自动弹出，确保每个咨询都能正确关联到相应的经销商。

**新增** 产品线经销商绑定管理功能允许管理员为产品线绑定多个经销商，支持动态添加和移除绑定关系，为后续的精准通知机制提供数据基础。

**更新** 客户服务工作流得到显著改进，包括transferTask方法的权限验证增强、submitForApproval方法签名更新支持审批原因参数、approveCurrentBpmTask方法增加原因支持，以及新的tab过滤功能（delivered和done状态）。这些改进大幅提升了系统的安全性和用户体验。

本模块采用前后端分离架构，前端使用Vue.js 3.0 + Element Plus构建用户界面，后端基于Spring Boot + MyBatis Plus实现业务逻辑，集成了BPM工作流引擎、WebSocket实时通信技术和通知系统。

## 核心组件

客户服务模块的核心组件包括：

### 1. 工单状态管理
- **待接单 (0)**: 新创建的工单状态
- **处理中 (1)**: 已被执行员接单的状态
- **已交付 (2)**: 执行员已完成处理的状态
- **已关闭 (3)**: 经销商验收通过的状态
- **已退回 (4)**: 经销商退回需要重新处理的状态

### 2. 会话状态管理（电商客服）
- **待处理 (0)**: 新创建的咨询会话状态
- **处理中 (1)**: 已被执行员接单的状态
- **已完成 (2)**: 处理员已完成处理的状态
- **已关闭 (3)**: 经销商关闭对话的状态

### 3. 咨询类型分类
- **签约**: 合同签署相关问题
- **政策**: 政策解读和咨询
- **售后**: 售后服务和维护
- **订单**: 订单处理和变更
- **基础数据**: 基础数据管理和查询
- **其他**: 未归类的其他事务

### 4. 工单紧急程度
- **紧急 (0)**: 需要立即处理
- **高 (1)**: 重要且紧急
- **中 (2)**: 正常处理优先级
- **低 (3)**: 一般性事务

### 5. 工单分类体系
- **签约**: 合同签署相关问题
- **政策**: 政策解读和咨询
- **售后**: 售后服务和维护
- **订单**: 订单处理和变更
- **数据**: 数据管理和查询
- **其他**: 未归类的其他事务

### 6. WebSocket消息类型
- **cs-chat-message**: 聊天消息推送
- **cs-session-event**: 会话事件通知
- **cs-new-consult**: 新咨询通知

### 7. 执行员产品线授权
- **执行员角色**: SERVICE_EXECUTOR
- **产品线授权**: 用户×产品线的授权关系
- **精准通知**: 基于角色×产品线交集的通知机制

### 8. BPM监听器类型
- **TASK_ASSIGNED**: BPM任务分配事件监听
- **PROCESS_COMPLETED**: BPM流程完成事件监听
- **流程监听器注册**: 自动注册机制

### 9. 工单标签过滤
- **all**: 全部工单
- **pending**: 待办工单（处理中+已退回）
- **claimable**: 可领取工单（待接单且未分配）
- **delivered**: 已交付工单（执行员视角）
- **done**: 已办结工单（执行员视角）

### 10. 经销商选择对话框
- **单选功能**: 支持用户手动选择经销商
- **自动选择**: 当只有一个经销商时自动选中

## 事件驱动的工单同步机制

**新增** 事件驱动的工单同步机制是本次更新的关键创新，通过监听BPM引擎的TASK_ASSIGNED事件，实现了精确的工单处理人同步，消除了时序竞争问题。

### 同步机制对比

| 同步方式 | 时序问题 | 数据一致性 | 实时性 | 复杂度 |
|---------|----------|------------|--------|--------|
| 主动轮询(syncBpmAssignee) | 严重时序竞争 | 无法保证 | 延迟 | 高 |
| 事件驱动(TASK_ASSIGNED监听) | 无时序竞争 | 强一致 | 实时 | 低 |
| 广播通知 | 无法保证 | 弱一致 | 实时 | 中等 |
| 精准匹配 | 无法保证 | 弱一致 | 实时 | 中等 |

### 时序竞争问题分析

**原有问题**：在创建工单时调用syncBpmAssignee方法，但BPM引擎尚未完成StartUserNode自动流转，导致过滤掉StartUserNode后未找到下一节点，造成assignee_id=null、status=PENDING的错误数据。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Service as "业务服务"
participant BPM as "BPM引擎"
participant Sync as "syncBpmAssignee"
Client->>Service : 创建工单请求
Service->>BPM : 发起流程实例
BPM->>BPM : StartUserNode自动流转
Sync->>BPM : 查询当前任务
BPM-->>Sync : 返回StartUserNode发起人
Sync->>Service : 更新工单assignee为发起人
Service-->>Client : 返回创建结果
Note over Service : 数据错误：assignee=发起人而非执行人
```

**更新后机制**：通过TASK_ASSIGNED事件监听，在BPM引擎完成任务分配后立即同步，确保获取到正确的处理人信息。

```mermaid

Listener->>BPM : 查询实际任务分配
BPM-->>Listener : 返回执行员任务
Listener->>Service : 更新工单assignee为执行员
Service-->>Client : 返回创建结果

```

## 性能考虑

客户服务模块在设计时充分考虑了性能优化，电商客服系统进一步提升了用户体验：

### 数据库优化
- **索引策略**: 为常用查询字段建立复合索引，包括状态、处理人、创建人、经销商编码、产品线编码等
- **序列化**: 使用数据库序列生成唯一ID，避免并发冲突
- **分区设计**: 支持按时间分区存储历史数据
- **连接池**: 优化数据库连接池配置，支持高并发访问
- **授权查询优化**: 为执行员产品线授权表建立唯一索引，提升授权查询性能
- **绑定关系优化**: 为产品线经销商绑定表建立唯一索引，确保绑定关系的唯一性

### 缓存策略
- **会话缓存**: 使用Redis缓存用户会话信息
- **配置缓存**: 缓存系统配置和枚举值
- **查询缓存**: 缓存热点查询结果
- **组件缓存**: 标签页组件状态缓存
- **消息缓存**: 最新消息缓存，减少数据库查询
- **授权缓存**: 执行员产品线授权缓存，提升通知匹配效率
- **标签计数缓存**: 工单标签页计数缓存，减少重复计算
- **经销商列表缓存**: 经销商选择对话框的经销商列表缓存
- **产品线绑定缓存**: 产品线与经销商绑定关系缓存

### 异步处理
- **消息队列**: 使用消息队列异步处理耗时操作
- **批量处理**: 支持批量数据导入导出
- **定时任务**: 异步清理过期数据
- **懒加载**: 标签页内容按需加载
- **WebSocket异步**: 实时消息推送采用异步处理
- **精准通知异步**: 执行员授权查询采用异步处理
- **BPM监听器异步**: 任务分配监听器采用事务后回调
- **审批原因异步**: 审批原因传递采用异步处理
- **组件状态异步**: DealerSelectDialog组件状态采用异步更新

### 前端性能优化
- **组件拆分**: TaskTab、OpReqTab、ConsultTab、ChatWindow、客户服务工作台组件独立加载
- **虚拟滚动**: 大数据量表格使用虚拟滚动
- **防抖节流**: 输入框和搜索功能使用防抖节流
- **图片懒加载**: 图片资源按需加载
- **WebSocket连接复用**: 多个组件共享WebSocket连接
- **模态窗口优化**: Teleport传送门减少DOM操作
- **组件状态缓存**: ChatWindow和客户服务工作台组件状态持久化
- **会话列表优化**: 咨询会话列表使用高性能渲染
- **标签页计数优化**: 工单标签页计数采用缓存机制
- **经销商选择优化**: DealerSelectDialog组件采用预加载和缓存机制
- **产品线绑定优化**: ProductLineDealerBindForm组件采用异步加载和分页显示

### 实时通信优化
- **心跳机制**: WebSocket自动心跳检测，保证连接稳定
- **消息去重**: 防止重复消息推送
- **离线消息**: 断线重连后同步历史消息
- **消息分页**: 大量历史消息分页加载
- **内存管理**: 及时清理不再使用的消息数据
- **批量操作限制**: 防止大量并发操作影响性能
- **精准匹配优化**: 执行员授权查询使用缓存和索引
- **事务安全**: 通知发送与数据库事务同步，确保数据一致性
- **审批原因优化**: 审批原因传递采用异步处理，避免阻塞主线程
- **组件状态同步**: DealerSelectDialog组件状态与后端数据保持同步

### BPM监听器性能优化
- **事件过滤**: 仅监听TASK_ASSIGNED事件，避免不必要的处理
- **条件过滤**: 过滤发起人节点和无处理人节点，减少无效操作
- **流程过滤**: 仅处理ops-cs-task流程，避免其他流程干扰
- **业务键解析**: 使用业务键直接获取工单ID，避免额外查询
- **事务后执行**: 使用afterCompletion回调确保BPM数据已落盘
- **状态检查**: 在更新前检查工单状态，避免不必要的数据库操作
- **权限验证优化**: 流程管理员权限检查采用缓存机制
- **通知发送优化**: 事件驱动的通知发送避免重复推送

### 工单标签页性能优化
- **标签计数缓存**: 工单标签页计数采用Redis缓存
- **视图范围缓存**: 用户视图范围采用会话缓存
- **过滤条件优化**: 标签过滤条件采用数据库索引优化
- **分页查询优化**: 大数据量查询采用分页和索引优化
- **候选人查询优化**: BPM任务候选人查询采用缓存机制

### 经销商选择对话框性能优化
- **预加载机制**: 组件打开时预加载经销商列表
- **缓存机制**: 经销商列表采用缓存机制
