# 采用共享 Composable 实现全模块客服咨询入口集成

_来源：4b587e4 → 49bb62d 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
客服系统核心功能（Step 7）已完成，但签约、订单、售后、基础数据等业务模块的咨询入口仍为占位符或缺失，且全局浮动按钮未挂载，导致客服能力无法闭环。

## 决策驱动
- 避免在各业务模块重复实现会话创建逻辑
- 统一咨询入口的交互体验
- 实现业务上下文（如合同号、订单号）自动带入

## 备选方案
- **在各业务模块独立实现咨询逻辑** _（已否决）_ — 优点：模块间耦合度极低；缺点：代码大量重复，会话去重和 WebSocket 监听逻辑难以统一维护
- **封装 useCsConsult Composable 并在 Layout 层挂载全局组件** — 优点：逻辑复用，统一处理会话创建、去重及 WebSocket 消息监听，各模块仅需传入上下文参数；缺点：引入了跨模块的 Hook 依赖，需确保 Context 参数的标准化

## 决策
新建 src/hooks/useCsConsult.ts 共享组合式函数，封装“创建/复用会话 → 打开 ChatWindow”的核心流程。在 src/layout/Layout.vue 中挂载全局浮动按钮与 ChatWindow 组件，并通过 WebSocket 监听实时消息。各业务模块（签约、订单等）通过调用该 Hook 并传入特定业务上下文（如 contractCode, orderCode）实现单条或批量咨询。

## 影响
实现了咨询功能在全系统的快速集成与统一维护；批量咨询时前端需并行发起多个会话创建请求，需注意限制并发数量以避免性能问题；基础数据模块需补充相应的菜单权限配置。
