# 重构系统消息推送架构以消除双重推送

_来源：7451d2e → 073df14 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
在会话生命周期事件（如接单、完成、关闭）中，系统消息既通过 `sendMessage()` 推送了 `cs-chat-message`，又通过 `sendSessionEventAsync()` 推送了 `cs-session-event`，导致前端收到重复通知。此前尝试在 HTTP VO (`CsMessageSendReqVO`) 中加入 `skipWebSocketPush` 标志作为临时修复，但这污染了接口层，违背了分层架构原则。

## 决策驱动
- 架构纯洁性：移除 HTTP VO 中对 Service 内部行为的控制标志
- 性能优化：减少前端不必要的 HTTP refresh() 请求
- 用户体验：避免同一事件的双重 WebSocket 推送
- 职责分离：明确区分用户聊天消息与系统状态消息的处理路径

## 备选方案
- **保留 skipWebSocketPush 标志** _（已否决）_ — 优点：改动最小；缺点：概念污染，VO 不应控制 Service 内部推送逻辑，技术债未解决
- **嵌入系统消息到会话事件 Payload（选定方案）** — 优点：彻底消除双重推送；前端直接在 ws 事件中追加消息，无需发起额外的 HTTP refresh() 请求；接口语义清晰；缺点：后端需新增内部 DTO (`CsMessageSaveCmd`) 和 Service 方法 (`saveSystemMessage`)；前端需适配新的 payload 结构并处理降级兼容

## 决策
删除 `CsMessageSendReqVO` 中的 `skipWebSocketPush` 字段。新建内部 DTO `CsMessageSaveCmd` 和 Service 方法 `saveSystemMessage`，仅负责落库而不触发 WebSocket 推送。在 `CsSessionServiceImpl` 中，将系统消息落库后，将其封装为 `SystemMessageVO` 嵌入到 `cs-session-event` 的 payload 中。前端接收到事件后，若包含 `systemMessage` 则直接追加到聊天面板并更新状态，否则降级调用 `refresh()`。

## 影响
后端消息服务职责更清晰，消除了 VO 层的逻辑泄露。前端在会话状态变更时不再发起额外的 HTTP 请求来获取消息列表，降低了服务器负载并提升了响应速度。普通用户聊天消息仍通过 `cs-chat-message` 正常推送，不受影响。
