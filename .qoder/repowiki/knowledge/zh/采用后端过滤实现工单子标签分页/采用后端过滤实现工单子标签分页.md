# 采用后端过滤实现工单子标签分页

_来源：ebb1cd2 → 9465c04 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
在拆分后的工单服务页面中，需要根据不同角色（发起方/处理方）展示不同的子标签（如“全部/待办”或“可领取/待办/已办”）。若采用前端过滤，会导致分页总数与实际展示数据不一致，影响用户体验和数据准确性。

## 决策驱动
- 分页准确性
- 大数据量下的性能
- 后端 API 通用性

## 备选方案
- **前端过滤** _（已否决）_ — 优点：后端无需改动，实现快；缺点：分页总数基于全量数据，切换子标签后页码和总数错乱，数据量大时性能差
- **后端支持 tabFilter 参数** — 优点：分页准确，支持大数据量，前端逻辑简单；缺点：需修改后端 VO、Service 和 Mapper，增加少量开发成本

## 决策
在后端 CsTaskPageReqVO 中新增 tabFilter、statusList 和 unassigned 字段。Service 层根据 viewScope 和 tabFilter 翻译为具体的查询条件（如 statusList=[2,4] 或 assigneeId=currentUserId）。Mapper 层支持 List<Integer> status 的 IN 查询和 unassigned 的空值判断。前端切换子标签时传递 tabFilter，由后端返回精确过滤的分页数据。

## 影响
工单列表的子标签切换将触发后端重新查询，确保分页总数和当前页数据严格匹配。后端 API 具备了更灵活的状态组合查询能力，可被其他场景复用。
