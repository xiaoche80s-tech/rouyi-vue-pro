# 引入「流程管理员」角色统一跨模块转派权限

_来源：32a9ec7 → 7451d2e 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
OpsHub 工单转派与 BPM 任务转派对“管理员”的定义不一致（OpsHub 包含 brand_admin，BPM 仅包含 process_admin/super_admin），导致品牌管理员在 OpsHub 转单时因 BPM 校验失败而报错。需建立统一的专用角色以支持跨模块的管理员级干预。

## 决策驱动
- 统一权限语义
- 最小化共享模块修改
- 职责分离

## 备选方案
- **新增 process_admin 角色并同步至 BPM/OpsHub** — 优点：职责清晰，无需修改 BPM 核心校验逻辑，权限可控；缺点：需维护新角色的菜单与数据权限配置
- **在 BPM 模块中直接兼容 brand_admin 角色** _（已否决）_ — 优点：用户无需切换角色即可操作；缺点：污染 BPM 通用模块的业务语义，增加耦合，且 brand_admin 可能不具备全局流程管理权限

## 决策
新增内置角色 process_admin (ID=161)，在 OpsHub 和 BPM 模块的转派逻辑中均将其识别为管理员。对于 OpsHub 中仍使用 brand_admin 的场景，通过在调用 BPM 接口时传入原处理人 ID 的方式绕过 BPM 的 assignee 校验，而非修改 BPM 核心逻辑。

## 影响
实现了管理员级转派的统一控制。OpsHub 层需承担额外的参数转换逻辑以兼容旧角色。需确保数据库脚本正确初始化该角色及其在两个模块中的菜单权限。
