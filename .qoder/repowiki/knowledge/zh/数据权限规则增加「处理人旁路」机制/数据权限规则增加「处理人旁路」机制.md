# 数据权限规则增加「处理人旁路」机制

_来源：32a9ec7 → 7451d2e 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
当 BPM 将工单分配给非该产品线默认范围的执行员时，现有的 DealerDataPermissionRule 会因产品线过滤条件导致执行员在待办/已办列表中看不到自己被分配的工单，造成业务阻塞。

## 决策驱动
- 业务可用性
- 数据安全性
- 最小侵入性

## 备选方案
- **在数据权限规则中增加 assignee_id 旁路 (OR 条件)** — 优点：确保分配给自己的工单始终可见，不破坏原有的产品线隔离逻辑，实现简单；缺点：略微增加 SQL 复杂度，需明确指定哪些表适用此旁路
- **放宽产品线数据权限范围** _（已否决）_ — 优点：彻底解决可见性问题；缺点：导致执行员看到大量无关产品线的工单，违背数据隔离原则

## 决策
在 DealerDataPermissionRule 中引入 assigneeBypassTables 机制，对 ops_cs_task 等表在生成数据权限 SQL 时追加 OR assignee_id = currentUserId 条件，确保处理人旁路生效。

## 影响
解决了跨产品线分配导致的工单不可见 Bug。需在配置类中显式注册需要旁路的表名。
