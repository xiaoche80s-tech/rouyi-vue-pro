- Controller 层普遍采用“查询基础数据 + 批量调用 API 获取关联信息（用户/部门/定义） + Convert 组装 VO”的模式，以减少 N+1 查询问题。
- Service 接口将方法按功能划分为 Query（查询）、Update（写入）、Event（事件）三类注释块，保持接口职责清晰。
- 涉及流程状态变更或任务操作的方法均添加 `@Transactional` 注解，并在必要时使用 `@DataPermission(enable = false)` 关闭数据权限以确保流程引擎内部查询的完整性。
- VO 类按业务域细分为 `task`、`instance`、`activity`、`cc` 等子包，并严格区分 ReqVO（请求）与 RespVO（响应）。
