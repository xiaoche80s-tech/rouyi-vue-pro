# 采用 WebSocket 实时推送与站内信异步通知并存的双通道策略

_来源：14276d8 → 3722ab2 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
工单状态变更和聊天消息需要即时触达用户，同时需要保留离线或未在线时的通知记录。单纯依赖 WebSocket 可能丢失离线消息，单纯依赖站内信缺乏实时性。

## 决策驱动
- 实时交互体验
- 消息可靠触达与留痕
- 多端通知覆盖

## 备选方案
- **仅使用 WebSocket 推送** _（已否决）_ — 优点：实时性最高；缺点：用户离线时无法接收，无持久化通知记录
- **仅使用站内信/短信** _（已否决）_ — 优点：可靠留痕；缺点：实时性差，无法支撑聊天场景
- **WebSocket + 站内信双通道** — 优点：WebSocket 保障在线实时刷新，站内信保障离线通知与历史查询；缺点：需在每个状态变更点同时调用两套 API

## 决策
保留 CsWebSocketService 用于实时推送聊天消息和工单状态变更帧；同时在 CsTaskServiceImpl 中注入 NotifyMessageSendApi，在关键状态节点（创建、接单、交付、验收等）发送站内信。

## 影响
提升了用户体验的实时性与通知的可靠性；增加了服务层的调用复杂度，需确保两种通知渠道的参数一致性。
