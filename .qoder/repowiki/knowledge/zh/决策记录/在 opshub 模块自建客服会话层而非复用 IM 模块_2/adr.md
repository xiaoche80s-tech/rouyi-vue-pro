# 在 opshub 模块自建客服会话层而非复用 IM 模块

_来源：14276d8 → 3722ab2 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
PRD 要求实现经销商与执行员之间的实时客服对话及工单联动。现有 IM 模块存在好友关系硬约束、前端全屏耦合以及数据污染风险，无法直接满足客服场景下轻量级、业务强关联的需求。

## 决策驱动
- 避免好友关系硬约束
- 解耦前端 UI 形态
- 防止业务数据污染

## 备选方案
- **复用现有 IM 模块** _（已否决）_ — 优点：无需重复开发基础聊天功能；缺点：强制要求好友关系，前端耦合度高，聊天记录与业务上下文难以关联
- **在 opshub 模块自建客服会话层** — 优点：数据结构贴合业务（支持上下文关联、工单卡片），前端可灵活定制为 Drawer 或工作台模式，无额外社交关系负担；缺点：需自行实现会话管理与消息推送逻辑

## 决策
在 yudao-module-opshub 中独立构建客服模块，设计 ops_cs_session 和 ops_cs_message 表，复用 infra 层的 WebSocketSenderApi 进行消息推送，不依赖 IM 模块的业务逻辑。

## 影响
实现了经销商侧轻量浮层与执行员侧工作台的差异化体验；支持在聊天中直接下发工单卡片；但需维护独立的会话状态机与消息存储逻辑。
