- **共享基础数据契约**：各子模块（订单、签约等）均依赖 `dealer` 模块提供的精简列表接口（`getSimpleDealerList`, `getSimpleProductLineList`）构建统一的筛选器与关联选择器。
- **统计驱动的业务流**：`order` 与 `signing` 模块采用“统计卡片/趋势图 + 筛选栏 + 业务表格”的标准化布局，并通过组件通信实现统计数据对列表过滤的联动。
- **模块化 API 组织**：在 `api/opshub` 目录下按业务域（basedata, dealer, order 等）物理隔离 API 定义，但共用统一的 `request` 实例与类型系统，确保前端请求层的一致性。
