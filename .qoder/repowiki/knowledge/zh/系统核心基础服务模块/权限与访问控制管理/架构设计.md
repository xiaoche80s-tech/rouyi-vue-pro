- **分层架构**：遵循 Controller-Service-Mapper 经典分层。Controller 层（`PermissionController`, `RoleController`, `MenuController`）处理 HTTP 请求；Service 层（`PermissionServiceImpl` 等）实现核心业务逻辑；Mapper 层（`RoleMenuMapper` 等）负责数据持久化。
- **API 暴露**：通过 `api/permission` 包下的 `PermissionApi` 和 `RoleApi` 向系统内其他模块提供跨模块调用的权限查询接口（如获取用户角色、角色菜单等）。
- **数据模型**：核心实体包括 `RoleDO`（角色）、`MenuDO`（菜单/权限点）、`UserRoleDO`（用户-角色关联）和 `RoleMenuDO`（角色-菜单关联），支持多对多权限映射。
- **缓存策略**：大量使用 Spring Cache（`@Cacheable`, `@CacheEvict`）配合 Redis 缓存用户角色、角色菜单等高频读取数据，并在权限变更时通过 `allEntries = true` 或指定 Key 确保缓存一致性。
- **事务管理**：在权限分配（如 `assignRoleMenu`）等涉及多表操作的方法上使用 `@DSTransactional` 保证多数据源环境下的事务原子性。
